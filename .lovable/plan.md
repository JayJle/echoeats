## 目标

把 Stage B 的聚簇逻辑从「同义/同向才合并」改成「**同一话题(维度)就合并并由 AI 取舍**」，方向相反也算同一簇——因为方向相反等于矛盾，需要取舍，不是不合并。

只有当条目代表**真正不同的子维度/不同阈值**时才拆成不同簇（典型：评分≥4.0 是必须项，评分≥4.3 是附加项 → 两个不同子标准，分开）。

## 只改一处

文件：`src/lib/echo.functions.ts`，只动 Stage B 的 `prompt`（349–382 行附近）。
schema、模型、兜底逻辑、Stage A/C **都不动**。

## 新 prompt 的核心规则

把现在的规则 1/3/6 换成「按话题聚簇 + AI 取舍」的版本，明确：

1. **聚簇按"话题/维度"**：只要 items 在谈同一件事（同一属性维度），就放进同一簇——
   - "环境好" / "环境不好" / "环境稍微好一点" / "环境一定要好" → **全部归到"环境"簇**
   - "中高端定位" / "不可低端" → **同一簇**（都在谈"档次定位"）
   - "不要游客店" / "本地人多的店" → 同一簇（都在谈"客群类型"）

2. **kind 不同(filter/dish/time)依旧不能跨簇**。

3. **方向相反 = 矛盾，要取舍，不是不合并**。winner 由 AI 选：
   - 用户后说的代表最新意图 → 通常优先
   - 语气更强/更明确的优先
   - 与整段诉求一致的优先

4. **只有"子维度/阈值不同"才拆簇**（这是唯一的不合并理由）：
   - "评分≥4.0 必须" vs "评分≥4.3 加分" → 两个不同阈值，**拆成 2 簇**
   - "预算≤10000" vs "预算≤15000 也行" → 同一阈值维度的强弱表达，**合并取舍**
   - "人数=2" vs "环境好" → 不同维度，**本就不同簇**

5. **每个 id 必须且只能出现在一个簇里**；winner 放数组首位。

6. 单独无同话题伙伴的 item → `[id]` 独成簇。

## 新示例（替换现有示例）

输入：
```
1 [filter] "环境稍微好一点" → 环境好
2 [filter] "环境一定要好" → 环境好
3 [filter] "环境不要太差" → 环境不差
4 [filter] "定位必须中高端" → 中高端
5 [filter] "不可低端" → 不要低端
6 [filter] "评分必须 4.0 以上" → 评分≥4.0 必须
7 [filter] "评分最好 4.3 以上" → 评分≥4.3 加分
8 [filter] "两个人" → 人数=2
```
输出：
```json
{"clusters":[[2,1,3],[4,5],[6],[7],[8]]}
```
说明（写进 prompt 注释里）：
- 1/2/3 同为"环境"话题（含方向相反/强弱不同）→ 合并，winner=2（语气最强且后置）
- 4/5 同为"档次定位"话题（方向相反但同维度）→ 合并取舍，winner=4
- 6 和 7 **阈值不同(4.0 vs 4.3)**且角色不同(必须 vs 加分) → 不合并
- 8 独立维度
